NotScribe turns a recorded English-language meeting into an accurate transcript and a structured written record (summary, minutes, key decisions and action items) through a coordinated three-model pipeline. Everything is generated by the pipeline from the uploaded audio; nothing is hardcoded. Where a task owner or deadline is not stated in the recording, it is shown as **Unspecified** rather than guessed.

---

## Features

- Upload an English meeting recording (`mp3, wav, m4a, mp4, mpeg, mpga, webm, ogg, flac`) and process it end to end in one run.
- Local speech-to-text with Whisper (no audio leaves your machine).
- **Stage 1 - transcript refinement** by one language model: fixes ASR errors in domain terms, acronyms and names, with an optional user-supplied glossary.
- **Stage 2 - documentation** by a separate language model: summary, minutes, key decisions, action items.
- Raw and refined transcripts are both retained and shown side by side for comparison.
- Live progress stepper for the three stages, with clear failure messages.
- Downloads: **PDF**, **Text** (human-readable) and **JSON** (machine-readable), plus each transcript as `.txt`.
- Clear error messages for unsupported, empty, or unreadable files.

## Models used and their roles

| Stage | Role                                             | Model (default)                                                      | Where it runs                |
| ----- | ------------------------------------------------ | -------------------------------------------------------------------- | ---------------------------- |
| 0     | Speech-to-text                                   | OpenAI Whisper `small.en` via **faster-whisper** (CTranslate2, int8) | Local (CPU or GPU)           |
| 1     | Transcript refinement (LLM #1)                   | `llama-3.3-70b-versatile`                                            | Groq (OpenAI-compatible API) |
| 2     | Minutes, decisions and tasks extraction (LLM #2) | `openai/gpt-oss-120b`                                                | Groq (OpenAI-compatible API) |

The two language-model roles are implemented as **distinct processing stages** with separate system prompts and separately configurable models (`REFINE_MODEL`, `EXTRACT_MODEL`). Any OpenAI-compatible provider can be used by changing `LLM_BASE_URL` and `LLM_API_KEY`.

If a configured model is not available to your API key, the app automatically falls back to the first available model from a preference list, and the exports/UI report the model that was **actually** used.

## How the pipeline works

```
 Upload (audio/video)
        |
        v
 [Validation]  extension, non-empty, size limit
        |
        v
 [Stage 0: Transcribe]  ffmpeg -> 16 kHz mono PCM -> faster-whisper (VAD on, greedy decoding)
        |  raw transcript (stored, shown in UI)
        v
 [Stage 1: Refine]      LLM #1 corrects ASR errors only (glossary-aware, chunked)
        |  refined transcript (stored, shown in UI)
        v
 [Stage 2: Extract]     LLM #2 -> JSON: summary, minutes, key_decisions, action_items
        |
        v
 [Meeting record]  -> view in UI -> download as PDF / TXT / JSON
```

How outputs move between stages:

1. **Transcribe** - the uploaded file is decoded by the system `ffmpeg` to raw samples and passed directly to faster-whisper. Output: `raw_transcript`.
2. **Refine** - `raw_transcript` is split into chunks of up to 8,000 characters (at sentence boundaries) to respect free-tier token limits; each chunk is edited by LLM #1 and the results are joined into `refined_transcript`. A guard falls back to the raw chunk if the model returns less than 60% of the input length (i.e. it summarised instead of editing).
3. **Extract** - `refined_transcript` (not the raw one) is passed to LLM #2, which returns strict JSON. The output is parsed, validated and normalised (empty owners/deadlines become `unspecified`).

The pipeline runs as a background job; the frontend polls the job status to update the stepper and show each result as soon as it exists.

## Setup and run instructions

### Prerequisites

- **Python 3.10+**
- **ffmpeg** available on your `PATH`
  - Windows: `winget install ffmpeg` (or download from ffmpeg.org and add to PATH)
  - macOS: `brew install ffmpeg`
  - Ubuntu/Debian: `sudo apt install ffmpeg`
  - Verify with `ffmpeg -version`. After installing, **restart your terminal** so the PATH update is picked up.
- **A free Groq API key** from https://console.groq.com (no credit card needed), or any other OpenAI-compatible provider key.
- **Internet access** on first run to download the Whisper model from Hugging Face (cached afterwards) and to reach the LLM API.

### 1. Get the code

```bash
git clone <your-repo-url>
cd <project-root>/backend
```

### 2. Create a virtual environment and install dependencies

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

`requirements.txt` should contain:

```
fastapi
uvicorn[standard]
python-multipart
python-dotenv
faster-whisper
numpy
openai
reportlab
```

### 3. Configure your API key

Create a file named `.env` inside `backend/`:

```env
GROQ_API_KEY=your_groq_api_key_here
```

(All optional settings are listed under [Configuration](#configuration).)

### 4. Start the server

From the `backend/` folder:

```bash
uvicorn main:app --reload
```

The Whisper model is loaded once at startup, so the first launch may take a while (model download). Watch the console for `Whisper model 'small.en' loaded.`

### 5. Open the app

Go to **http://127.0.0.1:8000** in your browser.

## Configuration

All settings are environment variables, set in `backend/.env`.

| Variable                       | Default                          | Description                                                                    |
| ------------------------------ | -------------------------------- | ------------------------------------------------------------------------------ |
| `GROQ_API_KEY` / `LLM_API_KEY` | _(required)_                     | API key for the LLM provider                                                   |
| `LLM_BASE_URL`                 | `https://api.groq.com/openai/v1` | Any OpenAI-compatible endpoint                                                 |
| `REFINE_MODEL`                 | `llama-3.3-70b-versatile`        | Model for Stage 1 (refinement)                                                 |
| `EXTRACT_MODEL`                | `openai/gpt-oss-120b`            | Model for Stage 2 (minutes/decisions/tasks)                                    |
| `WHISPER_MODEL`                | `small.en`                       | `tiny.en`, `base.en`, `small.en`, `medium.en` (bigger = more accurate, slower) |
| `WHISPER_DEVICE`               | `auto`                           | `auto`, `cpu` or `cuda`                                                        |
| `WHISPER_COMPUTE_TYPE`         | `int8`                           | `int8` is fastest on CPU; use `float16` on GPU                                 |
| `MAX_UPLOAD_MB`                | `200`                            | Maximum upload size                                                            |

Example for a different provider:

```env
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-...
REFINE_MODEL=gpt-4o-mini
EXTRACT_MODEL=gpt-4o
```

## Using the application

1. Select or drop an English-language meeting recording.
2. _(Optional)_ Open **Domain terms** and list acronyms or technical terms, separated by commas (e.g. `Kubernetes, F1 score, OKR`). These are passed to the refinement model as a glossary.
3. Click **Process**. Watch the three stages: _Transcribe audio_ -> _Refine terminology_ -> _Extract minutes & tasks_.
4. Compare the **raw** and **refined** transcripts side by side, then review the summary, minutes, key decisions and action items.
5. Download the full record as **PDF**, **Text** or **JSON**, or download either transcript on its own.
6. Click **Start over** to process another recording.

## Outputs

For every processed recording the application displays and offers for download:

| Output             | Contents                                                       |
| ------------------ | -------------------------------------------------------------- |
| Raw transcript     | Speech-to-text result before terminology correction            |
| Refined transcript | Transcript after domain-aware correction                       |
| Meeting minutes    | Concise summary plus main discussion points organised by topic |
| Key decisions      | Items the participants clearly agreed or decided               |
| Action items       | Task description plus owner and deadline (or `Unspecified`)    |

The meeting record is available in a human-readable format (PDF and TXT) and a machine-readable format (JSON). All formats are built from the same record, so they carry identical decisions and tasks.

## Error handling

Errors are shown in the interface with a clear message.

| Situation                            | HTTP status | Message shown                                               |
| ------------------------------------ | ----------- | ----------------------------------------------------------- |
| Unsupported file type                | 415         | Lists the supported extensions                              |
| File larger than limit               | 415         | States the size limit                                       |
| Empty file                           | 400         | "The uploaded file is empty."                               |
| Corrupt / undecodable audio          | 422         | "The audio file could not be read..."                       |
| No speech detected                   | 422         | "No speech was detected in the recording."                  |
| ffmpeg missing                       | 422         | Instructs to install ffmpeg                                 |
| LLM rate limit / auth / model errors | 502         | Specific guidance (wait, check key, check model name)       |
| Job expired or unknown               | 404         | "Job not found. It may have expired - please upload again." |

Unexpected failures are logged with a full traceback on the server and shown to the user as a generic message; a job is never left hanging.

## API reference

| Method | Route                             | Purpose                                                                  |
| ------ | --------------------------------- | ------------------------------------------------------------------------ |
| `GET`  | `/api/info`                       | Active models, supported extensions, upload limit                        |
| `POST` | `/api/jobs`                       | Upload a file (`file`) and optional `glossary`; returns `{job_id}` (202) |
| `GET`  | `/api/jobs/{job_id}`              | Job status, per-stage state, transcripts and record                      |
| `GET`  | `/api/jobs/{job_id}/export/{fmt}` | Download record; `fmt` is `json`, `txt` or `pdf`                         |

Jobs are kept in memory and purged after 2 hours.

## Design decisions to avoid invented content

- **Refinement prompt** restricts the model to correcting ASR errors. It must preserve names, numbers, dates, negation and commitment strength, may not summarise or add information, and must mark unsure passages as `[unclear]`.
- **Truncation guard** discards refinement output that is suspiciously short and keeps the raw chunk instead.
- **Extraction prompt** only counts clearly agreed items as _decisions_; proposals stay in the minutes. Only concrete, assigned follow-ups become _action items_.
- **Owners and deadlines** are only filled if explicitly stated; otherwise `null`, normalised to `unspecified` in code (also for values like `none`, `tbd`, `n/a`).
- Both prompts treat the transcript strictly as data and ignore instructions embedded in it.
- Models run at temperature 0 for repeatable output.
- Whisper runs with VAD filtering and `condition_on_previous_text=False` to reduce hallucinated text during silence.

## Limitations

- English-language audio only (`small.en` model and `language="en"`).
- One transcription runs at a time (shared model, high RAM use); additional uploads queue behind it.
- Job state is held in memory, so jobs are lost on server restart.
- No speaker diarisation: owners are only captured when named explicitly in the speech.
- Long recordings take longer on CPU; use a smaller `WHISPER_MODEL` or a GPU for speed.
- Free-tier LLM rate limits may slow or interrupt very long meetings (the app retries automatically before reporting an error).
- The PDF export substitutes a few glyphs (e.g. `₹`, `→`, `•`) that the built-in PDF font lacks.
